- **GOTCHA `_elf.h` (userspace):** o ELF embutido `src/kernel/<app>_elf.h` só regenera se `build/<app>.elf` recompilar. No fs nativo (ext4) o mtime é confiável e o rebuild é automático via Makefile; força bruta quando em dúvida: `make clean`.

## 4. Gotchas de automação (Linux nativo/QEMU) — aprendidos na unha

- **`/tmp` PERSISTE no Linux nativo** (no WSL não persistia entre invocações). Logs como `/tmp/xt.log` sobrevivem; ainda assim, guarde cópias em `build/logs/` quando quiser arquivar.
- **Shell é bash nativo (SEM wrapper PowerShell):** `$var`, aspas aninhadas e `$( )` chegam intactos ao bash. Para loops complexos prefira scripts `.sh` no repo (versionados, ex.: `scripts/_runtest.sh`) em vez de `bash -c` inline.
- `pkill -f qemu` **mata o próprio script** (casamento na linha de comando). Usar `pkill -x qemu-system-x86`.
- `kill -9 $!` **FUNCIONA** agora no Linux nativo (no WSL dava "Operation not permitted"); ainda assim `timeout 60 qemu ... &` é a prática padrão.
- QEMU `-serial file:` é rápido (grava direto em arquivo, não é UART real): o teste serial completo roda em microsseguendos/dentro de poucos ticks. `-serial stdio` (interativo) é lento e NÃO usar para automação.
- `grep -c "Novo admin"` sobre o serial é confiável no bash nativo (o artefato do wrapper PowerShell sumiu). Usar sempre `grep -a` (binário).
- Teclado PS/2 (QEMU sendkey): entrega provada com `scripts/_probe_ps2trace.sh` (events `pckbd_*`+`ps2_*`; enviar keycodes e cruzar com `[odig>` do drain). GOTCHA do probe: o flood de prints do SYS_READ (`[srr]` etc) empurra o prompt p/ fora da janela de 8KB do `wait()` → "login miss" e o script NÃO envia as sendkeys. Regra: manter o serial enxuto ou ampliar a janela. Validação determinística pré-login continua via `TEST=1`.
- **MATRIZ DE INJEÇÃO DE TECLAS — QEMU 10.0.11 headless + OVMF (validada na sessão WSL; histórico — revalidar no QEMU 8.2.2 nativo):**
  - `-display none` + **sem** `-device usb-kbd` + `sendkey` (HMP) ou cliente VNC RFB 3.8 → **funciona via PS/2** (`ps2_keyboard_event` 8×, `ps2_put_keycode` 12×). v1/v3.
  - **com** `-device usb-kbd` (qemu-xhci) → sendkey dispara `input_event_key_qcode` mas a tecla **NÃO chega a NENHUM handler** (ps2ev=0, `hid_kbd_queue_empty` 3×, 0 xfers EP3 IN) — **bloqueio do QEMU 10.0.11, não do driver**. v4 (display none), v5 (`usb-kbd,display=video0` + VNC client). QMP `input-send-event` = mesmo caminho (falha adicional: socket de v5 era HMP, não QMP).
  - Consequência: **teclado USB nativo NÃO é testável headless neste QEMU** (enumeração xHCI/HID-config OK, entrega de bytes impossível por injeção). Validação USB ⇒ hardware físico ou outro hypervisor.
- **GOTCHA QMP vs HMP (NOVA causa de "stall" falso de teclado):** `sendkey` via socket **QMP** é REJEITADO sem prévia negociação `qmp_capabilities` (erro `CommandNotFound: Expecting capabilities negotiation`) → nenhuma tecla chega e o login fica **na verdade esperando input** (parece stall de scheduler, mas é só ausência de teclas — o log fica parado em `Novo admin (nome):` com um byte solto `'` de origem não-teclado). Usar SEMPRE o monitor **HMP** (`-monitor unix:/tmp/qm6,server,nowait`) + `sendkey <key>` (sem negociação). Entre teclas usar delay ≈0.35-0.4s (probeM/clássico; envio rápido degrada a entrega).

## 5. Arquitetura / arquivos-chave

- `src/boot/thaisboot/` — bootloader UEFI original (PE32+ via GNU-EFI).
- `src/kernel/arch/x86_64/`
  - `boot.asm` — entry do kernel, GDT, long mode.
  - `idt.asm` — stubs de ISR/IRQ (`isr%1`, `isr_common_stub`), **troca de contexto por preempção acontece AQUI** (no nível do frame). Globais `g_int_no/g_err/g_fault_*`.
  - `ctxswitch.asm` — `context_switch` (park C) e `context_switch_first` (1ª execução). **Resume por frame IRQ também aqui.**
  - `usermode.asm` — `enter_user` (ring0→3 via iretq), `user_trampoline`, `syscall_gate` (int 0x80 → `syscall_dispatch`). **ATENÇÃO (raciocínio de scheduler): o vetor 0x80 é um INTERRUPT GATE (`0xEE`, idt.c:70) → `int` zera IF durante TODO o syscall → não há preempção dentro do gate/dispatch.** Preempção só ocorre com IF=1 (ring 3, ou ring 0 fora de syscall — ex.: appctl em C puro).
- `src/kernel/proc.c` — tabela de processos, scheduler (cooperativo + preempção por tick), `proc_exit`, `proc_gc_run`.
- `src/kernel/isr.c` — `irq_common_handler` (devolve alvo de preempção ao stub), `ticks`, panic de exceção.
- `src/kernel/testapp.c` — `appctl` serial (busy-wait com `while(!app_done(p)) sched_yield();`), `appctl_stress`.
- `src/kernel/init.c`/`login.c`/`keyboard.c` — `keyboard_get_line`/`keyboard_getc` são **busy-spin** (init nunca bloqueia/cede → fica sempre READY/RUNNING; é por isso que o scheduler "vê" init o tempo todo).
- `src/kernel/include/thais.h` — structs, protótipos, macros.

### Layouts e offsets (VERIFICADOS via probe em compile-time — conferir com `gcc scripts/_offset_probe.c`)
- `cpu_context_t`: `r15,r14,r13,r12,r11,r10,r9,r8` (0..64) | `rbp,rbx` (64..80) | `rip,rsp`(80..96) | `cr3`(96..104) | `arg1,arg2`(104..120) | `ran`(120..128) | `style`(u8, 128) | `hw_rsp`(uint64, 136). size=144.
- `process_t.ctx` offset = **0x60** (NÃO 0x40!). Dentro de `process_t`: `ctx.rip=0xB0`, `ctx.rsp=0xB8`, `ctx.cr3=0xC0`, `ctx.arg1=0xC8`, `ctx.arg2=0xD0`, `ctx.ran=0xD8`, `ctx.style=0xE0`, `ctx.hw_rsp=0xE8`. size(process_t)=**568 (0x238)** (re-verificado via `gdb -batch ptype /o` na sessão de snapshot); **`is_user`@0x104, `user_kstack_top`@0x108** (a sessão que leu `is_user=0` nos user procs usava offsets antigos — era artefato de leitura, não bug).
- Dentro de `cpu_context_t` (p/ `context_switch(from: cpu_context_t*, to)`): `rip+0x50`, `rsp+0x58`, `cr3+0x60`, `ran+0x78`, `style+0x80`, `hw_rsp+0x88`.
> Sempre que mexer no struct, revalidar com o probe (`/tmp/off`).

### Estilos de park/resume do scheduler (fix DO STALL — modelo novo)
- **Estilo C (style=0):** park voluntário via `sched_switch`→`context_switch` (appctl/fetch/echo ao ceder). `ctx.rsp` = return address na cadeia C; resume = `mov rsp; ret`. Usado na 1ª execução também.
- **Estilo IRQ (style=1):** park por preempção, **feito no `isr_common_stub`** (idt.asm): salva `ctx.hw_rsp`=base do bloco {14 GPRs + int_no/err + frame CPU} e `ctx.cr3`; resume = `mov rsp; pop 14; add rsp,16; iretq` — **nunca re-entra em cadeia C**.
- Quem faz o park marca o estilo: `context_switch` grava style=0 no `from` (park C); o stub grava style=1 em `g_isr_from` (park IRQ).
- **O resume do stub também decide por style:** `cmp byte [rax+0xE0],1`; style==1 → pop14/add16/iretq (hw_rsp=+0xE8); style==0 (park C) → `mov rsp,[+0xB8]; ret` (re-entra na cadeia C correta). Sem isso, um alvo parado por `sched_yield` era retomado por `iretq` com hw_rsp=0 fortuito → freeze. **CORRIGIDO na última sessão.**
- Alvo nunca executado (ran==0) → o stub e `context_switch` fazem 1ª entrada (argc/argv em rdi/rsi, zero callee-saved, `ret` p/ entry).
- **NUNCA editar offsets de ctx no asm sem conferir o probe.**

## 5.1 ARQUITETURA-ALVO (microkernel — bússola do projeto)

> Redefinida pelo usuário em sessão — **é o critério de decisão para qualquer continuação do desenvolvimento.**

**O que o projeto pede:** cada peça (auth, fs, synallagma, drivers) é um **serviço isolado em ring 3**, conversando só por syscall/IPC — nada de função de kernel chamada direto. O kernel fica o **mínimo possível** (scheduler, paginação, IPC, capabilities). Tudo o mais é **processo substituível/isolável**: um bug em `fs.c` não pode derrubar o sistema inteiro — deve derrubar só o processo do serviço.

**Já conquistado (real/testado):**
- Login + shell fora do ring 0 (spoudazo/praxia são apps ring 3).
- Modelo de serviço via IPC funciona (svc_register/svc_query; fsd/devd provados em teste; **authd provado em produção+TEST**).
- Isolamento de memória real entre processos ring 3 (W^X, PML4 próprio, GC de teardown).

**Ainda falta p/ ser o ideal (é o gap real):**
- vfs/fs/synallagma/crypto continuam **função de kernel** (acesso total). SYS_FS_READ/SYS_AUTH_* executam no kernel — auth tem o serviço authd (ABI 1.5) e o synallagma o serviço `synd` (ABI 1.6, dono do store userspace de contratos), ambos espelho do MESMO modelo (svc-first + fallback syscall; kernel = enforcement); os syscalls são o **fallback** quando `svc_query` falha.
- **authd (2026-09-11, ABI 1.5):** `/kormi/authd` dono da store+política; sessão por ticket `SYS_AUTH_TICKET_ISSUE`(36)+`SYS_SESSION_LOGIN(a3)`; **hash via `SYS_AUTH_HASH`(37) com IRQs off** — computo PBKDF2 em ring 3 preemptado é NÃO-DETERMINÍSTICO neste kernel (hash falhava intermitente; mesma classe do bugfix 2/3). Store+política+ticket estão no serviço; o kernel aplica no ponto de enforcement.
- **fs → serviço (preparação 2026-09-11):** boot/exec **desacoplado do ramfs** — `s_mods[]` file-scope (`fs.c`) + accessors `fs_mod_*`; `exec_embedded_args` (novo loader compartilhado `exec_elf_core`, sem `fs_read`); `kormi_start`/`session_entry` e `/bin`,`/kormi`,`/praxis` executam embedded-first com fallback FS p/ scripts/usuário. **`fsd` com superfície IPC completa** (`IPC_TYPE_FS_CREATE=11, WRITE=12, REMOVE=13, AUDIT=14` + READ/LIST), trilho de auditoria no heap do serviço, helpers `spud_fsd_*` (svc-first + fallback syscall). **Store userspace no fsd:** `/paradosis` e `/nomos` em cópia no heap do serviço (semente via `SYS_FS_LIST`/`SYS_FS_READ` no boot, marker `[fsd] store ring3: paradosis+nomos local no heap do servico (N arquivos)`); kernel = primitivo/fallback nos demais paths (modelo authd; split-brain boot-a-boot assumido — um fluxo por consumidor). **GOTCHA:** `SYS_FS_LIST` retorna **0** em sucesso (conteúdo no buffer; não é tamanho) — a semente tem de varrer até o NUL, não usar o retorno como tamanho. Sobra (próximo passo): migrar os ~93 usos internos do kernel para o serviço (classes boot/exec já desacopladas).
- fsd/devd ainda são demonstração; o fs ganhou esta sessão o enabler de exec + superfície IPC + store userspace próprio — a migração "de verdade" da camada interna do kernel é o próximo item.
- **Driver de teclado em processo ring 3 FUNCIONA** (`odigos_pliktrologiou`/'kbd', E2E scancode→login→shell provado); **ainda sem mouse/rede/HD como processos** e sem pilha USB nativa (EHCI/XHCI) — teclado USB depende do Legacy USB do firmware.
- Sem malloc de usuário + (agora já há) framebuffer por syscall → processos ring 3 fazem pouco além de texto + IPC pequeno (por isso Doom não roda).
- Preempção ring 3 tem histórico de bug; busy-wait ocioso (~622k trocas em 35s) é sintoma de sistema "não-ideal".
- Sem persistência, sem multiusuário simultâneo, sem COW/demand paging.

**Direção de prioridade (ex.:) 1º malloc userspace + APIs de dispositivo p/ destravar apps; 2º mover serviços core (auth/fs) p/ ring 3 isolado via os caminhos fsd/devd já provados; 3º driver real de teclado USB/rede como `/kormi`; 4º COW/demand paging.**

## 6. Bug-fixes históricos (CAUSA RAIZ — antes de re-abrir, ler isto)

1. **Heap corrompido / #UD com múltiplos ring 3** (✅ resolvido): frame iretq de 40B era ancorado em `ktop=kst+16368` e gravava até `kst+16408` — 24B além do bloco de 16KB → corrompia header do nó do heap (`[oikos] heap CORROMPIDO` com 2+ ring3). Fix em `proc_create_user_args`: frame ancorado no topo real (`kend=kst+PROC_STACK_SIZE`; `frame_base=kend-40`; trampoline/argc/argv abaixo; `user_kstack_top=kend`). Stress (`TEST=1 STRESS=1`) passou.
2. **Stall intermitente pós-exit do fetch (bug pré-existente) — ✅ em correção (ver seção 7):** processo preemptado era retomado por `mov rsp,ctx.rsp; ret` re-entrando na cadeia C do ISR (sched_switch→sched_yield→irq_common_handler). Funcionava só para certos depth de park (dados: FAIL parka init em rsp=0x1083a0; PASS em 0x108310..0x108360 — sensível a layout de frame, não a timing). Sintoma: QEMU vivo, sem hb/ticks crescentes (IF=0 perdido no resume), prossegue se appctl estiver READY no momento.
3. **`auth.c:48-51`** registra sintoma pré-existente da MESMA classe: "Com IRQs/preempcao ativas, o ISR do PIT sobre o kernel stack corrompia o estado durante o hash (#PF em sha256_*)... Root cause do ISR ainda sob investigacao". Re-avaliar após fechar seção 7.
4. Excep-ções/uint: ring0 exceptions → `kernel_panic_exception` (halt). Ring3 fault precisaria de handler próprio (TODO).
5. **Corrupção de heap 0x100000 / #GP no kfree (✅ RESOLVIDO — CAUSA RAIZ: RAX não preservado no ISR):** o `isr_common_stub` salva os GPRs do processo interrompido SEM **RAX** (caller-saved). Interrupção é assíncrona — NÃO há fronteira de função — então qualquer código de kernel usando RAX como ponteiro vivo entre chamadas C ficava sujeito a clobber. O `fb_clear` (fill do framebuffer) mantém o ponteiro de pixels em RAX; quando o PIT interrompia o laço, o handler C "sujava" RAX e o `iretq` retomava com ponteiro lixo → `bg_color` (0x000a0a12, mesmo do splash) era gravado na heap (0x100000…). Evidências: dump do walk do kfree = fill uniforme `0x000A0A12` (size == `0x000A0A12000A0A12`); trap #DB (DR0=0x100000) flagrou `mov %ebx,(%rax)` em `fb_clear` (rip 0x1f12/0x1f60) sem relação com g_fb.addr=0x80000000. Fix: **`push rax` como PRIMEIRA instrução do stub** (antes de qualquer `mov rax,…` — senão grava RSP e não o RAX interrompido — foi o bug intermediário), `pop rax` APÓS `pop r15` nos 4 caminhos de resume (`idt.asm` `.resume_iret`/`.no_switch`; `ctxswitch.asm` `context_switch` e `context_switch_first`), e `.diag_iret` usa `r10` em vez de RAX. Hipótese alternativa descartada: US=1 no clone do PML4 (paging_new_address_space clona as 512 entradas do PML4 do kernel = supervisor; ring-3 nunca escreveria 0x100000). Validado: `_runtest.sh 8` 8/8 PASS e `TEST=1 STRESS=1` PASS.
6. **`[hello] args:` sem argv → PF no hello ring 3 (✅ RESOLVIDO — CAUSA RAIZ: syscall_gate NÃO preserva caller-saved):** `main` do hello guarda `argv` em r9 (registrador que o kernel C usa/destrói). A primeira `SYS_WRITE` (`[hello] args:` imprime) passava pelo antigo `syscall_gate` que só salvava rbp → no `iretq` o r9 do app voltava com lixo de kernel (`argv=0xffffff`) → `cmpq (%r9,%r8,8)` → **PF err=0x5 (user READ em página supervisor), CR2=0xffffff**. Fix (ABI 1.0): `syscall_gate` agora **empilha/restaura TODOS os 15 GPRs**, devolvendo intactos ao ring 3 — só RAX = resultado (`usermode.asm`). Validado: `[hello] args: mundo bar` em ring 3 + `_runtest.sh` 4/4 e 8/8 PASS.
7. **Bug intermitente de preempção — PF #UD no appctl/init com frame de outro processo (✅ FECHADO — causa raiz: janela `current_proc`/IRQ no scheduler):** em `sched_yield`/`sched_block`/`sched_tick` o flip global `current_proc=to` era feito com IF=1 e o `cli` só vinha dentro de `sched_switch`. Um PIT entre os dois fazia o ISR estacionar o ALVO com um frame do processo que RODAVA de fato (stack do processo real) → ctx corrompido (regs de spoudazo/rodata, RIP=0xa1404, etc.). ## 9. Observações de runtime (úteis)
